# RULING: the supporting line is one component for every page (Kain, in Code's sitting, 11 November 2026)

## 1. Kain's words

Code had told him the course page's eight supporting lines were still drawn the old way, with the words set in from the orange bar, and offered to show it before and after on the course page. Kain: "I think a couple of sessions ago, we agreed we would essentially make this a component which means that this problem isn't just assigned to this page, it's on all pages. So we need a permanent fix here for all pages. Do you understand what I'm saying here? Do you know what that solution needs to be?"

His rule on the bar itself, given in the Certification sitting the same day and carried here by that session: "We have one simple rule ... all text lines up against the container, which means that the little orange hairline sits actually outside of the actual text container."

## 2. What the record shows today (read this turn)

- DSRD 7 section 3.3 makes Lead with Bar the type of every block's supporting line and quotes Kain asking for "a website-wide standard". Its "Where it is built" paragraph says it is built on the course page and on /certification/, "scoped to that page", and that "Every other page moves onto it only under the signed sweep brief, which waits on the workbook programme".
- The Component Registry's table "Shared features: one home each" lists the reading line, the grey list dot, the link hover wash, Thin Edge and No Lone Words. The supporting line is not on it.
- In the theme the look is drawn page by page: the course page's stylesheet carries it on eight selectors of its own, and the Certification and Accreditation stylesheets carry their own rules. That is why his bar rule was mended on Certification at 0.707.944 and is still not on the course page.

So the standard is site-wide on paper and page-local in the build. That gap is the fault he is naming.

## 3. The permanent fix, as Code put it to him

1. The supporting line is built once: one rule in one home file that every page loads, under one class, carrying section 3.3's type and edge and his bar rule (the words on the container's edge, the bar hanging outside it).
2. Every page that shows a supporting line switches it on with that one class. Each page's own copy is taken out: the course page's eight, Certification's, Accreditation's.
3. It is listed in the Component Registry's shared features table with its home file, so the registry's birth gate refuses any stylesheet that draws it anywhere else.
4. The supporting line check built at S476 (paused on its branch) is wired into the page gate, so every page is held to the one component.
5. The pages that have no supporting line yet, or one of the wrong length, move onto it under the sweep brief section 3.3 names. That half needs words, so it is yours to brief.

Nothing is built yet. Steps 1 to 4 are a theme job for the three page kinds that already have the look; Code proposed doing it in a fresh session because this one is long.
